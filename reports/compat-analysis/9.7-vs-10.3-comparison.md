# 9.7 修复版 vs 10.3 修复版插件对比 + openclaw 8.1–10.3 兼容性矩阵

**日期**: 2026-10-14
**背景**: 小七排查报告（https://lcnw3g3m1zn6.feishu.cn/docx/JZILdbtgNoyVMexmFMrcSHJCnZf ）确认 9.7 插件在 10.3 加载失败（`ERR_PACKAGE_PATH_NOT_EXPORTED`），服务器已全量回滚 9.9 + clawhub 重装 9.7 插件恢复正常。本文对比 9.7 与 10.3 两个插件版本，验证 10.3 修复版对 openclaw 8.1–10.3 全线的兼容性。

---

## 一、小七报告分析（关键点确认 + 两处补正）

### 确认无误（与本地实证完全吻合）
1. **根因一**：10.3 移除 `openclaw/plugin-sdk/command-auth` → 9.7 插件静态 import 失败 → `ERR_PACKAGE_PATH_NOT_EXPORTED`（小七日志）——本地 10.3 SDK 实测复现**同一错误码**
2. **根因二**：schema 19→20 迁移 + 旧 build 拒开新库 → code-only 回滚无效
3. **升级脚本缺陷**：只看 `/health` 不看插件加载数/通道 → 误报成功

### 两处补正（新实证）
1. **"只升 10.2"也不安全**：小七称"稳定线 10.2，可只升到 10.2"——本地实证 **openclaw 10.2 已移除 command-auth**（exports 无声明 + `dist/plugin-sdk/command-auth.js` 文件已删除，仅剩 command-auth-native）。**9.7 插件在 10.2 上同样加载失败**，与 10.3 同因。
2. **"10.2 无 API 硬墙"评估失效**：10.2 与 10.3 同为 10.x 线，均无 command-auth 子路径；破坏性变更起始于 10.x 线（非 10.3 独有）。

## 四、给当前部署的建议

服务器现状：openclaw 9.9 + clawhub 渠道 9.7 插件（正常）。

1. **当前状态可稳定运行**，无需立即动作；
2. 后续升级 openclaw 本体（无论 10.2 还是 10.3），**必须先装 10.3 修复版插件**（兼容 9.9 与 10.x）：
   ```bash
   openclaw plugins install npm-pack:/root/backups/hotwvpyym-openclaw-lark-2026.10.3.tgz --force --accept-capabilities
   openclaw config validate        # footer 等配置合法
   openclaw plugins list | grep openclaw-lark   # 2026.10.3
   ```
3. 然后升级核心：`openclaw update`（目标 10.3 稳定线）→ `openclaw gateway restart`；
4. 升级验收按小七建议加硬指标：插件加载数=4、飞书三账户在线、真实收发一条测试消息（不能只看 /health）；
5. 回滚预案三档：code-only / code+升级前 state / full-state（避免再丢 state）。
